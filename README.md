# Монитор доступности сайтов

Тестовое задание: сервис, который периодически проверяет доступность URL,
ведёт историю и журнал инцидентов, шлёт письма при падении/восстановлении и
показывает live-статусы на панели и на публичной странице.

> Документ заполняется по ходу работы. Разделы, помеченные *(TBD)*, будут
> дописаны на соответствующих этапах.

## Архитектура

| Сервис            | Что это                                                    | Порт на хосте |
|-------------------|------------------------------------------------------------|---------------|
| `postgres`        | PostgreSQL 16 — единственное хранилище                     | —             |
| `backend`         | Node.js 22 + TypeScript + Fastify + Prisma: API, планировщик, SSE, почта | 3000 |
| `frontend`        | React + TypeScript + Vite, отдаётся nginx, `/api` проксируется на backend | 8080 |
| `maildev`         | Эмулятор SMTP с веб-интерфейсом для просмотра писем        | 1080          |
| `target-emulator` | Заглушка «проверяемых сайтов» с управляемым поведением     | 4000          |

### Почему Node.js для backend

Домен — десятки параллельных I/O-bound HTTP-проверок с таймаутами. Event loop
Node.js естественно подходит под эту нагрузку: каждая проверка — независимая
асинхронная задача, медленный или зависший сайт просто держит открытый сокет
и не блокирует ни другие проверки, ни обработку запросов интерфейса. Пул
потоков для этого не нужен.

## Как развернуть локально

### Пререквизиты

- Docker 24+ с Docker Compose v2 (проверялось на Docker 29.5, Compose v5.1)
- Свободные порты 8080, 3000, 1080, 4000 (меняются в `.env`)
- Node.js 22+ — только если нужно запускать скрипты проверки/разработку вне Docker

### Запуск

```bash
cp .env.example .env
docker compose up --build
```

- Панель: http://localhost:8080 (логин/пароль — `ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`)
- MailDev: http://localhost:1080
- Backend healthcheck: http://localhost:3000/api/health
